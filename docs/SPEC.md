# מסמך אפיון – אתר מתכונים חכם

## תקציר והנחות יסוד

אתר מתכונים פתוח לכולם, ללא הרשמה, עם ארבעה פיצ'רים חכמים המבוססים על OpenAI Responses API: חיפוש לפי מצרכים, סינון מתקדם, ערכים תזונתיים משוערים והתאמת מתכון עם עוזר צ'אט. המערכת קטנה במכוון: עד 100 מתכונים, שרת אחד, מסד נתונים אחד.

| נושא | החלטה |
| --- | --- |
| גישה | האתר פתוח לכולם, ללא הרשמה והתחברות |
| מקור מתכונים | כל מבקר יכול להעלות; פרסום רק אחרי אישור ידני של מנהל |
| נפח | עד 100 מתכונים בשלב הראשון |
| סטאק | React, Python/FastAPI, PostgreSQL |
| חיפוש לפי מצרכים | ה-AI מקבל את כל המתכונים (בייצוג מקוצר) ומדרג |
| ערכים תזונתיים | הערכת AI בעת אישור המתכון, נשמרת במסד |
| תקציב | לא נכלל במערכת |
| התאמת מתכון | תצוגה זמנית, עם אפשרות לשמור כמתכון חדש (עובר אישור מנהל) |
| עוזר צ'אט | בהקשר המתכון הפתוח, יכול להפעיל התאמה דרך Tool |
| כשרות | שדה חובה: בשרי / חלבי / פרווה, וחלק מהסינון |
| הגבלת שימוש | ללא מגבלה בשלב הראשון; תיעוד צריכת טוקנים |
| שפה ותמונות | עברית ואנגלית, תמונה אחת למתכון |

## היקף ה-MVP

כל ארבעת הפיצ'רים נכנסים לגרסה הראשונה, ושלושה מהם מבוססים על AI.

| פיצ'ר | מימוש | שימוש ב-AI |
| --- | --- | --- |
| חיפוש לפי מצרכים | המבקר מזין רשימת מצרכים; השרת שולח ל-AI את כל המתכונים המאושרים בייצוג מקוצר ומקבל רשימה מדורגת עם המרכיבים החסרים | פלט מובנה |
| סינון מתקדם | שאילתת SQL רגילה: זמן הכנה, רמת קושי, סוג כלים, מספר מנות, כשרות | ללא |
| ערכים תזונתיים | הערכה למנה (קלוריות, חלבון, פחמימות, שומן) בעת אישור המתכון, נשמרת במסד ומסומנת "משוער" | פלט מובנה |
| התאמת מתכון | בקשה חופשית או כפתורים מוכנים; מחזיר מתכון מלא באותה סכמה; ניתן לשמור כמתכון חדש | פלט מובנה |
| עוזר בישול | צ'אט בהקשר המתכון הפתוח, עם streaming; יכול להפעיל את כלי ההתאמה | Tools + streaming |

**מחוץ להיקף:** הרשמה ומשתמשים, מועדפים, דירוגים ותגובות, סינון תקציב, חיפוש סמנטי, הגבלת שימוש, רשימת קניות.

## ארכיטקטורה וסטאק

אפליקציית React סטטית, שרת FastAPI אחד ומסד PostgreSQL אחד; OpenAI הוא השירות החיצוני היחיד. ספריות: בלקוח Vite ו-react-i18next; בשרת SQLAlchemy, Alembic, Pydantic ו-SDK הרשמי של OpenAI.

הארכיטקטורה: לקוח, שרת אחד, שלושה שירותים. רק `ai_service` פונה ל-OpenAI. ה-Recipes API מפעיל אותו עבור החיפוש, ההתאמה והצ'אט, וה-Admin API מפעיל אותו באישור מתכון; כל קריאה נרשמת ב-`ai_usage_log`.

## מודל נתונים

שתי טבלאות בלבד. המרכיבים והשלבים נשמרים כ-JSONB בתוך המתכון, כי ב-100 מתכונים אין צורך בנרמול, וכך מבנה הטבלה זהה לסכמת הפלט המובנה של ה-AI.

| servings | INT | מספר מנות |

## שכבת ה-AI

כל הקריאות ל-OpenAI יוצאות משירות אחד בשרת (`ai_service.py`), דרך Responses API ב-SDK של Python. מפתח ה-API ושם המודל מוגדרים במשתני סביבה (`OPENAI_API_KEY`, `OPENAI_MODEL`), והלקוח לעולם אינו פונה ל-OpenAI ישירות. כל קריאה נרשמת ב-`ai_usage_log`.

### סוגי קריאות

| קריאה | מופעלת על ידי | קלט | פלט | Streaming |
| --- | --- | --- | --- | --- |
| fridge_search | המבקר, במסך החיפוש | רשימת מצרכים + כל המתכונים המאושרים בייצוג מקוצר (id, title, שמות מרכיבים), אחרי סינון SQL אם נבחר | FridgeSearchResult | לא |
| estimate_nutrition | המנהל, בלחיצה על "אשר" | מרכיבים, כמויות ומספר מנות | NutritionEstimate | לא |
| adapt_recipe | המבקר (כפתור או טקסט חופשי) או ה-Tool בצ'אט | המתכון המלא + הוראת ההתאמה | AdaptedRecipe | לא |
| chat | המבקר, בחלונית הצ'אט | ההודעה + `previous_response_id`; בהודעה הראשונה גם המתכון המלא בהוראות | טקסט חופשי + אירועי Tool | כן (SSE) |

### סכמות פלט מובנה

כל הסכמות מוגדרות כמודלי Pydantic ונשלחות במצב strict דרך `client.responses.parse(..., text_format=Model)`. אין צורך בפענוח JSON ידני.

- **FridgeSearchResult:** `matches[]`, לכל פריט `recipe_id`, `match_score` (0 עד 100), `missing_ingredients[]`. השרת מסנן מזהים שאינם קיימים ומחזיר עד 10 תוצאות.
- **NutritionEstimate:** `calories`, `protein_g`, `carbs_g`, `fat_g` (למנה), ו-`confidence` (low, medium, high). מוצג באתר עם סימון "ערכים משוערים".
- **AdaptedRecipe:** כל שדות המתכון שה-AI רשאי לשנות (title, description, servings, prep_minutes, difficulty, equipment, kashrut, ingredients, steps), ובנוסף `changes_summary[]` לתצוגה, ו-`feasible` (boolean) עם `reason` כשלא ניתן לבצע את הבקשה. השדה `kashrut` מחושב מחדש לפי המרכיבים החדשים.

דוגמת קריאה:

```python
class FooResult(BaseModel):
    bar: list[str]
    baz: int

response = client.responses.parse(
    model=settings.openai_model,
    instructions=SYSTEM_PROMPT_FOO,
    input="Lorem ipsum dolor sit amet",
    text_format=FooResult,
)
result = response.output_parsed
```

### Tools בצ'אט

הצ'אט מקבל שני כלים מסוג function, במצב strict. ה-AI מחליט מתי להפעיל אותם, והשרת מבצע אותם.

| Tool | פרמטרים | מה השרת עושה | מה חוזר למודל |
| --- | --- | --- | --- |
| adapt_recipe | `instruction: string` | מריץ את קריאת adapt_recipe ושולח ללקוח אירוע `recipe_adapted` עם המתכון המותאם | `changes_summary` בלבד, כדי לחסוך טוקנים |
| scale_servings | `servings: integer` | מחשב כמויות חדשות בקוד, ללא AI, ושולח ללקוח אירוע `recipe_scaled` | רשימת הכמויות החדשות |

לולאת הכלים: השרת קורא ל-Responses API; אם בפלט יש פריט `function_call`, הוא מבצע את הכלי ושולח תוצאה כ-`function_call_output` עם אותו `call_id`, יחד עם `previous_response_id`. הלולאה מוגבלת ל-3 סבבים בכל הודעה.

### כללים בהוראות המערכת

- לענות בשפת ההודעה של המבקר (עברית או אנגלית).
- בצ'אט: לענות רק על שאלות הקשורות להכנת המתכון הפתוח.
- בהתאמה: לא ליצור מתכון המשלב רכיבים בשריים וחלביים; אם הבקשה מחייבת זאת, להחזיר `feasible: false` עם הסבר.
- לא להמציא מתכונים שאינם ברשימה בחיפוש לפי מצרכים.

## נקודות קצה של ה-API

כל הנתיבים תחת `/api`. נתיבי הניהול דורשים כותרת `Authorization: Bearer <ADMIN_TOKEN>`, שמונפק בהתחברות עם סיסמת המנהל.

| שיטה ונתיב | גישה | תיאור |
| --- | --- | --- |
| GET /recipes | ציבורי | רשימת מתכונים מאושרים; פרמטרים: lang, max_minutes, difficulty, equipment, servings, kashrut, q |
| GET /recipes/{id} | ציבורי | מתכון מאושר מלא |
| POST /recipes | ציבורי | הגשת מתכון חדש (multipart: נתונים + תמונה); נשמר בסטטוס pending |
| POST /ai/fridge-search | ציבורי | גוף: ingredients[], lang, ומסננים אופציונליים; מחזיר מתכונים מדורגים עם מה שחסר |
| POST /ai/adapt | ציבורי | גוף: recipe_id, instruction; מחזיר AdaptedRecipe |
| POST /ai/chat | ציבורי | גוף: recipe_id, message, previous_response_id; מחזיר SSE |
| POST /admin/login | ציבורי | גוף: password; מחזיר טוקן |
| GET /admin/recipes?status=pending | מנהל | תור מתכונים לאישור |
| PUT /admin/recipes/{id} | מנהל | עריכת מתכון לפני אישור |
| POST /admin/recipes/{id}/approve | מנהל | מריץ estimate_nutrition, שומר ומפרסם |
| POST /admin/recipes/{id}/reject | מנהל | דחייה |

שמירת מתכון מותאם משתמשת ב-`POST /recipes` עם השדה `source_recipe_id`, ועוברת את אותו תור אישור.

אירועי SSE של הצ'אט: `text_delta` (קטע טקסט), `tool_started` (שם הכלי), `recipe_adapted` (אובייקט AdaptedRecipe), `recipe_scaled` (כמויות חדשות), `done` (כולל `response_id` לשמירה בלקוח), `error`.

## מסכים וממשק משתמש

חמישה מסכים ציבוריים ושניים לניהול. הממשק דו-לשוני: עברית בכיוון RTL ואנגלית בכיוון LTR, עם מתג שפה בכותרת; כל טקסטי הממשק בקובצי תרגום (react-i18next), ו-`dir` של המסמך מתחלף לפי השפה. רשימת המתכונים מציגה מתכונים בשפה שנבחרה.

| מסך | רכיבים עיקריים |
| --- | --- |
| דף בית ורשימת מתכונים | חיפוש טקסט, פאנל סינון (זמן הכנה, קושי, כלים, מנות, כשרות), כרטיסי מתכונים עם תמונה |
| מה יש לי במקרר | שדה הזנת מצרכים כתגיות, כפתור חיפוש, תוצאות מדורגות עם אחוז התאמה ותגית "חסר" לכל מרכיב חסר |
| דף מתכון | פרטים, מרכיבים, שלבים, ערכים תזונתיים משוערים, כפתורי התאמה מהירים, שדה התאמה חופשי, חלונית צ'אט צדדית |
| תצוגת מתכון מותאם | השוואה למקור, רשימת השינויים, כפתור "שמור כמתכון חדש" |
| הגשת מתכון | טופס עם כל השדות, העלאת תמונה, הודעת אישור "המתכון ממתין לאישור" |
| ניהול: התחברות | סיסמה בלבד |
| ניהול: תור אישורים | רשימת ממתינים, עריכה, אישור או דחייה |

בחלונית הצ'אט, `previous_response_id` נשמר ב-state של הקומפוננטה בלבד; רענון הדף מתחיל שיחה חדשה. כשמגיע אירוע `recipe_adapted`, נפתחת תצוגת המתכון המותאם.

עיצוב: ראו [`design/index.html`](design/index.html) (פלטת צבעים, גופנים, כרטיסים ותגיות כשרות).

## ניהול ואישור מתכונים

מנהל יחיד, בלי טבלת משתמשים: סיסמה אחת המוגדרת במשתנה סביבה (נשמרת כ-hash ב-`ADMIN_PASSWORD_HASH`), שמונפק בעבורה טוקן JWT לתוקף של 12 שעות.

זרימת האישור:

1. מבקר מגיש מתכון; הוא נשמר בסטטוס pending, והתמונה נשמרת בתיקייה זמנית.
2. המנהל רואה את התור, פותח מתכון ויכול לערוך כל שדה.
3. בלחיצה על "אשר", השרת מריץ `estimate_nutrition`, שומר את הערכים, מעביר את התמונה לתיקייה הציבורית ומשנה סטטוס ל-approved.
4. בלחיצה על "דחה", הסטטוס משתנה ל-rejected, והתמונה נמחקת אחרי 7 ימים.
5. אם קריאת ה-AI נכשלת באישור, המתכון מאושר בכל זאת עם `nutrition = null`, והמנהל יכול לקרוא שוב ל-approve כדי להריץ את החישוב מחדש.
