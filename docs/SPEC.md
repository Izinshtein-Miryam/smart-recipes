# אפיון אתר מתכונים חכם – גרסה 2

תאריך: 03/11/2026

## מטרות המוצר וקהל היעד

אתר מתכונים בעברית (RTL), רספונסיבי, שמשלב שלושה פיצ'רים חכמים מבוססי OpenAI API: ניווט חכם, יצירה חכמה והמלצה למתכון. זה פרויקט לימוד והדגמה שרץ על מחשב מקומי בלבד.

קהל היעד רחב ומעורב, ממתחילים ועד מבשלים מנוסים. לכן כל מתכון מסווג לפי רמת קושי.

מדדי הצלחה (לפי סדר חשיבות):

1. **איכות הקוד:** מבנה נקי ומודולרי, כיסוי בדיקות של 70% לפחות ב-Backend, טיפוסים מלאים ו-README ברור.
2. **איכות היצירה החכמה:** כל מתכון שנוצר עובר ולידציה במלואו, בלי ערבוב בשר וחלב, עם כמויות ויחידות לכל רכיב ושלבים ברורים.
3. משתמש מוצא מתכון רלוונטי תוך פחות מ-3 פעולות.

## פיצ'ר 1: ניווט חכם

שלושה ערוצי כניסה מובילים לאותה תוצאה: רשימת מתכונים מסוננת מתוך הקטלוג.

1. **השלמה אוטומטית:** בזמן ההקלדה מוצגות עד 8 הצעות משמות מתכונים, רכיבים וקטגוריות. החיפוש מקומי לחלוטין (בלי AI), מבוסס טבלת הרכיבים המרכזית, עם debounce של 200ms.
2. **חיפוש בשפה חופשית:** המשפט נשלח ל-OpenAI (מודל GPT), שמחזיר JSON מובנה של מסננים: סוג, קטגוריה, זמן מקסימלי, קושי, רכיבים לכלול או להוציא ומגבלות. המסננים מוצגים כצ'יפים שאפשר להסיר.
3. **צ'אט עוזר:** כפתור צף בכל העמודים שפותח חלון צדדי. העוזר מנהל שיחה קצרה, שואל שאלת הבהרה אחת לכל היותר ומחזיר עד 3 כרטיסי מתכון מהקטלוג. השיחות לא נשמרות, וכל פתיחה מתחילה שיחה חדשה.

**כשאין תוצאות:** המערכת מציעה להסיר את המסנן המגביל ביותר, למשל "נמצאו 6 מתכונים בלי מגבלת הזמן". בנוסף מוצג כפתור "צור לי מתכון", שמעביר ליצירה החכמה עם הבקשה כבר ממולאת.

כללים:

- ה-AI מפרש את הבקשה בלבד, והשליפה עצמה נעשית מהמסד, כך שלא מוצג מתכון שלא קיים.
- הצ'אט עוסק במתכונים בלבד ומסרב בנימוס לשאלות מחוץ לתחום.
- אם ה-API לא זמין, החיפוש עובר לחיפוש טקסט רגיל.

## פיצ'ר 2: יצירה חכמה

המערכת מייצרת מתכון אחד מלא בכל יצירה, במבנה זהה למתכוני הקטלוג. כפתור "נסה שוב" יוצר גרסה אחרת לאותה בקשה.

| מצב | קלט | פלט |
| --- | --- | --- |
| מרכיבים | רשימת רכיבים (צ'יפים עם השלמה), מספר מנות, סוג בשרי/חלבי/פרווה | מתכון חדש שמבוסס על הרכיבים שהוזנו |
| מתיאור חופשי | משפט כמו "מנה קלה לארבעה בחצי שעה" | מתכון חדש שעומד בדרישות |
| התאמת מתכון | מתכון קיים + בקשה (החלפת רכיב, קיצור זמן, ללא גלוטן) | גרסה מותאמת עם סימון השינויים |

כללים:

- **רכיבים מותרים:** במצב "מרכיבים" ה-AI רשאי להוסיף רק רכיבי בסיס מתוך רשימה מוגדרת (מלח, פלפל, שמן, מים, סוכר ותבלינים יבשים). כל רכיב נוסף מסומן בפלט כ"רכיב שלא הוזן".
- הפלט מוצג ב-streaming. בסיומו הוא חייב להתאים ל-JSON Schema (כותרת, תיאור, רכיבים עם כמויות ויחידות, שלבים, זמן, קושי, סוג, תגיות) ועובר ולידציה ב-Pydantic. אם הולידציה נכשלת, מתבצע ניסיון חוזר אחד אוטומטי.
- כל רכיב בפלט ממופה לטבלת הרכיבים, והסוג שלו נבדק. אם נמצא ערבוב בשר וחלב, המתכון נדחה ונוצר מחדש.
- מתכון שנוצר מוצג בלי תמונה, עם אייקון לפי סוג המנה, ומסומן "נוצר ב-AI".
- משתמש רשום יכול לשמור את המתכון לאוסף האישי שלו. פרסום לקטלוג עובר דרך מנהל תוכן, ורק אז נוצרת לו תמונה.
- מכסה: לאורח 3 יצירות ביום, למשתמש רשום 20. מנהל המערכת יכול לשנות את הערכים בהגדרות.

## פיצ'ר 3: המלצה למתכון

ההמלצה משלבת שני מנגנונים: הקשר זמן ודמיון בין מתכונים. שניהם רצים מקומית, בלי קריאה ל-AI בכל טעינת עמוד. בשלב זה אין משוב מהמשתמש על ההמלצות.

- **הקשר זמן (דף הבית):** מתכון מובחר אחד בגדול, ומתחתיו 4 המלצות נוספות, עם כותרת שמתאימה לזמן ("מתאים לארוחת ערב"). הבחירה נעשית לפי כללי שעה ויום. בבוקר מוצגות מנות מהירות וקלות, ובערב מנות עיקריות. בימים ה' ו-ו' מוצגים מתכונים להכנה מראש ולאירוח. מנהל התוכן מסמן תגיות זמן (בוקר, צהריים, ערב, הכנה מראש).
- **דמיון (עמוד מתכון):** בלוק "מתכונים דומים" עם 4 מתכונים. הדמיון מחושב מ-embedding שנוצר פעם אחת בשמירת המתכון, בשילוב חפיפת רכיבים ותגיות.
- **סינון קשיח:** המלצה מתוך עמוד מתכון שומרת כברירת מחדל על אותו סוג (בשרי/חלבי/פרווה), ומכבדת את מגבלות התזונה שהמשתמש בחר.

ציון סופי = 0.6 × דמיון + 0.3 × התאמת זמן + 0.1 × פופולריות. מנהל המערכת יכול לשנות את המשקלות בהגדרות.

## ליבת האתר

**סיווג מתכונים.** לכל מתכון ארבעה צירי סיווג:

- סוג: בשרי / חלבי / פרווה (שדה חובה).
- סוג מנה: ראשונה, עיקרית, תוספת, קינוח, מאפה.
- זמן ורמת קושי.
- מגבלות תזונה: ללא גלוטן, ללא סוכר, ללא אגוזים וכדומה.

**עמוד מתכון.** העמוד כולל תמונה, תגיות, רכיבים ושלבים ממוספרים. יש בו בורר מספר מנות שמחשב את הכמויות מחדש, כפתור מועדפים וכפתור "הוסף לרשימת קניות". כפתור "התאם לי" מעביר ליצירה החכמה. בנוסף יש גרסת הדפסה (CSS print), קישור לשיתוף וכפתור "התחל לבשל".

**רשימת קניות מאוחדת.** רשימה אחת שמצטברת מכמה מתכונים. רכיבים זהים מאוחדים לפי טבלת הרכיבים, והכמויות שלהם מחוברות כשהיחידות תואמות. לכל פריט יש סימון V, ואפשר להסיר פריט או לנקות את כל הרשימה. הרשימה ניתנת להדפסה ולהעתקה.

**מצב בישול.** מסך מלא עם ארבעה רכיבים:

- שלב אחר שלב, בטקסט גדול עם כפתורי "הבא" ו"הקודם" ותמיכה בהחלקה במגע.
- טיימר אוטומטי לכל שלב שמוגדר לו זמן, עם התראה קולית בסיום.
- מסך שלא נכבה, באמצעות Wake Lock API.
- הצגת הרכיבים הרלוונטיים לכל שלב, לפי קישור בין רכיבים לשלבים.

**ממשק ניהול תוכן.** טופס מתכון עם שמירת טיוטה, פרסום והסתרה, וטבלת מתכונים עם חיפוש.

**ממשק מנהל מערכת.** יש בו ארבעה מסכים: ניהול משתמשים (יצירת מנהלי תוכן, השבתה ומחיקה), הגדרות מערכת, סטטיסטיקות (שימוש ב-AI, עלויות ומתכונים פופולריים) ויומן פעולות.

**תמונות מתכונים.** התמונות מטופלות דרך Google Gemini (Imagen), מאחורי ממשק `ImageProvider`. יש שני מסלולים, ובשניהם המנהל מאשר את התוצאה לפני פרסום:

1. **יש תמונה ביתית:** המנהל מעלה תמונה, והמודל משפר תאורה, רקע וקומפוזיציה כך שתיראה מקצועית.
2. **אין תמונה:** המודל יוצר תמונה לפי הנחיות המנהל. אם המנהל לא נתן הנחיות, התמונה נוצרת לפי שם המתכון, רכיביו ותיאורו.

כל בקשה למודל התמונות כוללת הנחיית מערכת קבועה: התמונה מציגה את המנה בלבד, ללא דמויות אדם, ידיים או טקסט. המקור והגרסה המעובדת נשמרים שניהם, כך שאפשר לחזור למקור. בסביבת פיתוח ובבדיקות משתמשים ב-`MockImageProvider`.

## מודל נתונים

הנתונים נשמרים ב-SQLite, דרך SQLAlchemy 2, עם Alembic למיגרציות.

| טבלה | שדות עיקריים |
| --- | --- |
| users | id, email, password_hash, display_name, role (user/content_manager/sysadmin), is_active, dietary_prefs (JSON), created_at |
| ingredients | id, name, aliases (JSON), category (ירקות, מוצרי חלב, בשר, מזווה...), kosher_type (meat/dairy/parve), is_basic, default_unit |
| recipes | id, title, slug, description, kosher_type, dish_type, prep_minutes, cook_minutes, difficulty, servings, time_tags (JSON), diet_tags (JSON), status (draft/published/hidden), source (admin/ai), owner_id, embedding (BLOB), view_count, created_at, updated_at |
| recipe_ingredients | id, recipe_id, ingredient_id, quantity, unit, note, order |
| recipe_steps | id, recipe_id, order, text, timer_seconds, ingredient_ids (JSON) |
| recipe_images | id, recipe_id, original_path, processed_path, origin (upload/ai_edit/ai_generate), prompt, is_primary, approved |
| favorites | user_id, recipe_id, created_at |
| shopping_list_items | id, user_id, ingredient_id, quantity, unit, source_recipe_ids (JSON), checked |
| settings | key, value (JSON), updated_by, updated_at |
| audit_log | id, actor_id, action, entity_type, entity_id, details (JSON), created_at |
| ai_calls | id, user_id, feature (search/chat/generate/image), model, input_tokens, output_tokens, cost_usd, latency_ms, status, created_at |

הטבלה `kosher_type` של כל רכיב משמשת לבדיקת ערבוב, לחישוב אוטומטי של סוג המתכון ולאיחוד ברשימת הקניות. מתכון שנוצר ביצירה החכמה נשמר עם source=ai, status=draft ו-owner_id של המשתמש.

## ארכיטקטורה וטכנולוגיות

המערכת בנויה משני תהליכים מקומיים: React קורא ל-FastAPI, ורק FastAPI מדבר עם מסד הנתונים ועם ספקי ה-AI. מפתחות API נשמרים בצד השרת בלבד, בקובץ `.env`.

| שכבה | טכנולוגיה |
| --- | --- |
| Frontend | React + TypeScript + Vite, React Router, TanStack Query, Tailwind עם תמיכת RTL |
| Backend | Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2, Alembic |
| מסד נתונים | SQLite בקובץ מקומי |
| קבצי תמונות | תיקייה מקומית `media/`, מוגשת כ-static |
| טקסט ופענוח שפה | OpenAI API (OpenAI Python SDK, מודל GPT), פלט מובנה ב-JSON |
| Streaming | Server-Sent Events בצ'אט וביצירה החכמה |
| Embeddings לדמיון | מודל מקומי רב-לשוני (sentence-transformers) |
| עיבוד ויצירת תמונות | Google Gemini (Imagen), מאחורי ממשק `ImageProvider` |
| התחברות | JWT ב-cookie מסוג httpOnly, סיסמאות ב-bcrypt |

שכבת הטקסט (OpenAI) משמשת לטקסט ולפענוח שפה בלבד, ותמונות ו-embeddings מוגדרים כרכיבים נפרדים. כל קריאה ל-AI עוברת דרך שכבת שירות אחת, שרושמת אותה בטבלת `ai_calls`.

**הפעלה מקומית:** הפעלה ישירה, `uvicorn` לשרת ו-`npm run dev` לממשק. סקריפט עזר `dev.sh` (ו-`dev.ps1` ל-Windows) מריץ את שניהם, ופקודת `seed` טוענת את 50 מתכוני הדמה.
